A quick overview of syntax. Will be split into multiple pages down the line.

Type instances

Base types

Base types, primitves or custom types, are just identifiers.

Generics during use

Generics are delimited with <, ,, and >. They can include types (template types) or values (typically dimensions).

Generics contain expressions that resolve to either a type or value.

Generics during definitions

When using types, the syntax for a given generic is subtype : type T : supertype, where T is an identifier, subtype is an optional type that extends T, and supertype is an optional type that T extends. The two constraints are not mutually exclusive. Each colon should only be present if the "bounding type" is present.

When using vales, the syntax is T value, where T is a type, and value is an expression that would satisfy the constexpr keyword from c++.

Arrays

Arrays are created with brackets, and proceed the rest of the type. The syntax for arrays is [n]T, where n is an (optional? I want opinions about how this should work in different contexts) length and T is a type.

Pointers

Pointers are created with asterisks and amperstands, and proceed the rest of the type. The syntax is *T or &T, where T is the type. The difference is pointers created with & are not allowed to be nullnull.

References

References are created with the ref keyword, followed by the type. The syntax is ref T, where T is the type. References work like immutable non-null pointers to (by default) mutable values with automatic dereferencing.

Constants

Constants are created with the const keyword, followed by the type. The syntax is const T, where T is the type. Constants cannot be writeen to, and all members of a constant record are treated as if they had a const keyword added to the start of the type.

Structures

Structures are unnamed types, this language's version of tuples. struct{int x, int y} is a structure with two integers, and can be used in place of a type. This structure is considered identical (for puruposes of implicit casting) to any other structure with the same types in the same order.

Nesting examples

  • [3][4]int - Array of 3 arrays of 4 ints.
  • [3]*[4]int - Array of 3 pointers to arrays of 4 ints.
  • ref const int - Reference to a constant integer.
  • const *int - Constant pointer to a mutable integer.
  • *const int - Mutable pointer to a constant integer.

"Primitives"

Primitives are not intended to be considered part of the spec: they should all be constructable from scratch and annotations. However, the following primitives should probably be defined in most cases:

  • int
  • long
  • byte
  • short
  • float
  • double
  • uint
  • ulong
  • ubyte
  • ushort
  • bool
  • char (8 bit character)
  • wchar (16 bit character)
  • string (technically going to be typedef string : String<char>), where String represents a list with specific properties, similar to a vector.

Typedefs

Type definitions include classes, structures, unions, union structures, enums, enum classes, interfaces, and raw typedefs.

Records are a subtype of typedefs. They store data contiguously by name in memory. They include classes, structures, and enum classes.

Classes are named records. They store data in one spot, as a named type, and are not considered identical even to otherwise identical classes with different names. They are declared with the class keyword.

Structures are unnamed records. They are nearly identical to classes, except they are considered identical (and can thus be implicitly cast) to any other structure with the same order of types.

Enum classes are enumerations where each element of the enumeration is an instance of the class. Think Java style enums.

Other types aren't records:

Raw typedefs give an alternate name to another type, and are intended to be shorthands for very long types. They are declared with typedef NewName : T, where NewName is the name of the typedef, and T is the type it is equivalent to. Both sides are always considered the same type.

Enums essentially give names to numbers automatically. Similar to enum classes, where only some values are valid. Think C# style enums.

Interfaces encapsulate functionality between unlike classes.

Unions and union structs are very similar: they work like classes and structures respectively, but all of the values are overlapping. It has use cases, like viewing an IPv4 as either [4]ubyte or int. Note that union structures don't have names, and that the order now is commutative and only counts up to 1 instance of a given type.

Memory management functions

C++ memory management functions (destructors, move assignment operators, copy assignment operators, copy constructors, and move constructors) are a little unintuitive. Cleaner syntax is:

All of these functions exist on any type and are automatically generated like c++, unless explicit deletion by the user happens (syntax to come-undecided on what it is. Open to ideas!). The user cannot delete the initializer.

new copy(ref const T other) {...}

new move(ref T other) {...}

copy(ref const T other) {...}

move(ref T other) {...}

delete() {...}

We also add custom initalizers and default constructors, with syntaxes

init() {...}

new() {...}

Initializers run before any constructor, no matter which it is. The default constructor runs if a value is left uninitialized, as opposed to a no-arg constructor which requires explicit calling. If no no-arg constructor is defined, the default constructor runs if it is called. If no default constructor exists but a no-arg does, the no-arg is used as the default.

Dereferencing

The dereference operator (*) has a higher precidence than any other unary operator, as well as having a higher precidence than the access operator (.). This means *a.b evaluates to (*a).b, not *(a.b). The dereference can also be placed immediately after an access operator, or immediately before a computed member access. a.*b is treated identically to *(a.b), and this can be chained. The syntax a*[b] is also allowed, and evaluates to *(a[b]), while *a[b] evaluates to (*a)[b]. Finally, methods consider the method to be one "identifier", so a*(b) is not allowed, and *a(b) evaluates to *(a(b)).
